The earlier diagnostic probe was moved by the user, who reported normal size with a brief black flash. Its numerical log exposed a stale-monitor minimum-size defect, corrected in this version. See [DPI investigation](dpi-investigation.md).

The user then tested the installed v1.4.1 diagnostic candidate on the actual desktop:

| Evidence | Observed result | Scope |
| --- | --- | --- |
| Font size | The user reported normal size | This run only; not universal multi-monitor coverage |
| Cross-monitor presentation | The black flash persisted | Visual acceptance has not passed |
| Taskbar helper state | Ready / displaying was reported | Helper and control-path status only |
| Taskbar on screen | The user could not see any data | Taskbar visibility acceptance has failed despite the reported state |

The test instance was closed after the observation. That candidate was **not published**. These failures prompted the R2 investigation below; they remain part of the history rather than the latest observed outcome.

Hidden fixtures validate geometry, rectangle/API handling and generated alpha pixels. They do not validate how Explorer composes the actual taskbar surface, its layering or final visible pixels. A successful drawing/window API call or a `displaying` status is not proof of on-screen visibility. Likewise, the corrected DPI minimum and a normal-size report do not establish flash-free presentation.

Raw diagnostic logs and local configuration remain private local evidence and are excluded from source commits and release archives. This document retains only the deidentified outcome, not the evidence directory, monitor layout or user data.

## Follow-up diagnostic candidate (R2)

The taskbar candidate now explicitly submits its bitmap size while preserving the existing window position. Client-size sampling, rasterization and upload run under the child window's DPI awareness context; the caller's context and any upload error are restored afterward. The first direct-size attempt enlarged an unaware child in the hidden fixture, and was rejected. The scoped version passed 108 native taskbar checks, including all three awareness contexts, repeated unchanged/changed frames and cleanup-error preservation. These results do not establish actual Explorer visibility.

They require diagnostics and isolated-instance flags together, never persist the probe policy and leave ordinary startup unchanged. The updated suites passed 63 diagnostic checks and 193 native window checks. Both variants still require a separate program directory and copied configuration for live use; the instance flag alone does not isolate storage.
